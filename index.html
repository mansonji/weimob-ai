团队赛 · 三大赛道

以「项目组」为单位，1—10 人，个人也可单独成组

第一步：你要报哪个赛道

先看清楚每条赛道要什么，再对号入座。同一个项目组可以重复报名、报名多个赛道。

¥业务价值赛道
用 AI 做出可量化的业务成果——营收增长、成本下降、转化率或留存率提升。
自测：这个项目赚了多少钱 / 省了多少钱？能不能落到一张真实的经营或财务报表上？
★创新价值赛道
用 AI 做出公司现在还没有的新场景、新模式、新方法，需要有能跑起来的 Demo 原型。
自测：这是个以前没人做过的新玩法吗？我能当场演示出来吗？
⚡组织提效赛道
用 AI 改写工作流——让重复性作业的耗时或人力投入显著下降，且已在实际工作中落地使用。
自测：这件事以前要多久、现在要多久？团队是不是每天都在用？
三个都沾边怎么办？按这个顺序判：
  1. 能拿出经营 / 财务系统数据证明指标变化 → 报业务价值
  2. 拿不出财务数据，但能算清耗时 / 人力差 → 报提效
  3. 只有 Demo、还没有真实数据 → 报业务创新
一个项目只能报一个赛道；同一个项目组可以提交不同赛道。

演示材料选交。Demo 录屏 / 可运行链接 / 关键截图，作为评审与述职的辅助。

第三步：项目说明文档必须包含这些

A · 通用部分（三条赛道都要写）
  1. 项目基本信息 项目名称、所属赛道、项目组名称、项目负责人、成员
  2. 业务场景说明 锚定微盟哪个业务域 / 场景
  3. AI 方案说明 如何使用 AI 实现业务价值提升 / 业务创新 / 提效；如何复用
  4. 附录 Skill 打包文件说明（包内不得包含密钥、业务数据等敏感信息）、参考资料、数据来源
B · 赛道专属部分（只写你报的那条赛道）

▸ 业务价值赛道

  1. 业务目标与基线 改造前该项指标是多少——注明数据来源、统计口径、时间区间
  2. 成果数据 改造后指标的变化，须标明取自哪个经营 / 财务 / 业务系统
  3. ROI 测算 投入（人力/时间/成本）与产出（增收/降本）对比，给出量化结论

▸ 创新价值赛道

  1. 创新点说明 这个场景 / 模式新在哪；此前业务中是否已有类似做法
  2. Demo 演示 可运行原型 / 录屏 / 演示链接，含操作路径
  3. 价值想象空间 跑通后能带来什么，下一步推广计划，市场空间有多大

▸ 组织提效赛道

  1. 提效前后对比 同一件事改造前的人力 / 耗时 vs 改造后，须给具体数字
  2. 提效幅度计算 写清计算公式与基数来源（例：单次 40 分钟 → 8 分钟，提效 80%）
  3. 使用频次与范围 多少人、多高频在使用，已嵌入哪个日常流程
评审按此清单逐项核对，缺项会影响评分。文档内所有数据须真实可追溯，不得虚假填报。
